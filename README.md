# 차선 전처리 및 Sliding Window 검출

운영진 피드백을 기준으로 최종 전처리 출력은 차선만 남깁니다. 횡단보도, 정지선, 얇은 주차 구획선은 차선 후보에서 제외하며 동일한 마스크를 Sliding Window에 전달합니다. 이전에 요청했던 노면 표시 전체 보존 모드는 기본 처리에서 제거했습니다.

실행: `python main.py`. 창 없이 전체 저장: `python main.py --headless --output-dir updated_results`.
Space: 일시정지/재생, s: 캡처, q/Esc: 종료. 필요 패키지: opencv-python, numpy.

ROI는 640×480 기준 (80,260), (559,260), (639,479), (0,479)의 좌우 대칭 사다리꼴이며 입력 해상도에 비례합니다. 네 꼭짓점을 640×500 BEV 네 모서리에 대응시킵니다. 양쪽 차선이 원본 화면 밖으로 나가는 구간에서는 없는 차선을 복원하지 않습니다.

전처리 순서:
1. ROI 내부 흰색 도색을 밝기·채도·주변 대비로 추출합니다.
2. 가장 큰 어두운 무채색 노면 성분과 인접한 도색을 선택합니다. 특정 초록색이나 매트 경계에서 화면 한쪽 전체를 차단하지 않습니다.
3. BEV에서 긴 가로 선분과 과도하게 넓은 도색으로 정지선을 제거합니다. 실선과 접하는 교차 부위는 일부 끊길 수 있습니다.
4. 비슷한 폭·간격으로 가로 반복되는 줄무늬로 횡단보도를 제거합니다. 반복 부분에 잠깐 닿는 실제 차선까지 통째로 지우지 않도록 반복 비율을 검사합니다.
5. 크기·높이·두께로 얇은 구획선과 작은 잡음을 제외합니다. 차선 중앙을 거리 마스크로 파내는 처리는 사용하지 않습니다.

과제 2는 12개 Sliding Window를 아래에서 위로 이동시켜 왼쪽 파란색, 오른쪽 빨간색으로 표시합니다. 하단에 가중치를 둔 히스토그램으로 시작점을 정하고 행별 관측 중심에 2차 곡선을 맞추며, 짧은 관측에서는 이전 곡률을 참고하는 제약을 연속적으로 적용합니다. 현재 프레임에서 관측이 부족하면 LOST와 JSON null을 기록합니다. 과거 검출은 다음 탐색 위치에만 사용하며 현재 검출로 표시하지 않습니다.

4단 비교 화면: ROI → BEV → 차선 이진화 → Sliding Window.
결과 파일은 실행할 때 덮어씁니다. 최신 결과는 updated_results 폴더에 있습니다.
- result_comparison.mp4: 4단 비교
- result_binary.mp4: 횡단보도·정지선 등을 제외한 차선 전처리
- result_sliding_window.mp4: 좌우 차선 검출
- result_lanes.jsonl: 프레임·시간·좌우 다항식 계수와 관측 범위

미리보기 이미지는 검증 코드를 실행하면 updated_results/qa에 생성됩니다. 임시 이미지는 정리해도 실행에 영향을 주지 않습니다.
검증: `python verify_preprocessing.py --output-dir updated_results`, `python verify_lane_detection.py`.
합성 정지선·횡단보도·구획선 제거, 연결된 차선 및 점선 보존, 배경색 변경, 두꺼운 차선 중앙 보존, 실제 횡단보도 프레임, 검출 누락, 출력 영상 및 로그 전체를 검사합니다.

한계: 고정 밝기·채도·형태 임계값을 쓰므로 다른 조명·노면에서는 조정이 필요합니다. 이 검사는 배경색 변경에 대한 회귀 검사이며 모든 트랙에 대한 일반화를 입증하지 않습니다. 차선과 형태가 비슷한 도색은 일부 남거나 차선이 누락될 수 있습니다. BEV는 거리·조향각 계산용 카메라 보정이 아니며 정답 라벨 기반 정확도 평가나 조향각 계산은 포함하지 않습니다.

## 잔여 표시 제거 보완

최종 result_binary.mp4는 이제 단순 흰색 후보 마스크가 아니라, 현재 프레임에서 Sliding Window로 선택한 좌우 차선의 실제 관측 픽셀만 포함합니다. 내부 동작은 흰색 후보 → 횡단보도/정지선/가는 선 제거 → 좌우 추적 → 경로에 일치하는 관측 run 선택 → 최종 차선 마스크 순서입니다. 따라서 화면의 3번은 추적 이후 선택된 차선 마스크이며, 4번은 같은 추적 결과의 창과 피팅 곡선을 보여 줍니다. 과제 1의 독립 후보 이진화와 최종 선택 결과를 구분해야 합니다.

BEV 전에 원본에서 너무 가는 구획선 성분을 제외합니다. 최종 선택에서는 관측된 행과 좌우 차선 곡선에 맞는 흰 띠 하나만 남기고, 주변의 별도 흰 물체·구획선은 버립니다. 다른 픽셀을 새로 그리지 않으며 추적 실패 시 해당 쪽은 비웁니다. 화면 끝에 일부만 들어오는 횡단보도도 반복 패턴의 간격으로 검사합니다.

검증에는 실제 차선과 별도 흰 사각 물체·구획선을 섞은 합성 장면이 추가됐습니다. 실제 차선의 픽셀만 남는지와 빈 공간에 픽셀을 만들어 넣지 않는지를 확인합니다. 이 변경은 오검출 억제를 우선하므로 흐리거나 크게 휘는 실제 차선 일부가 누락될 수 있습니다. 모든 프레임에서 의미상 완벽하게 차선만 분류한다는 보장은 없으며, 예시 이미지와 영상으로 결과를 확인해야 합니다.

## 차선이 짧아지거나 사라질 때의 표시

기존에는 관측 높이가 120px 미만이면 1차식으로 전환하고, 픽셀이 없는 창의 중심을 고정해 회색 박스를 세로로 늘어놓았습니다. 이 때문에 곡선이 갑자기 직선으로 바뀐 것처럼 보였습니다.

현재는 항상 세 계수의 2차식 x=a*y^2+b*y+c를 사용합니다. 짧은 관측에서는 곡률 계수 a가 이전 검출에서 급변하지 않도록 제약하고, 관측이 길어질수록 제약을 연속적으로 줄입니다. 위치와 기울기는 현재 픽셀로 갱신합니다. 이전 관측이 없는 짧은 첫 검출은 곡률을 확정할 수 없어 작은 곡률 쪽으로 제한합니다. 따라서 2차식이라고 반드시 눈에 띄게 휘어지는 것은 아닙니다.

박스는 현재 관측한 높이 범위와 겹치는 것만 표시합니다. 점선 사이의 공백에 있는 회색 창은 남기지만 관측 범위 밖으로 길게 이어지는 회색 꼬리는 숨깁니다. 완전 소실 시 현재 검출은 LOST, 마스크와 표시 선/박스는 비웁니다. 이전 곡선을 새 관측처럼 출력하지 않습니다.

JSON curvature_source는 observed(충분한 현재 관측), previous(짧은 관측에서 이전 곡률 참고), weak_observation(이전 곡률 없이 짧은 첫 관측) 중 하나입니다. 완전 소실은 해당 쪽 전체가 null입니다. 긴 곡선 → 짧은 상단 관측 → 완전 소실을 재현한 회귀 검증을 포함합니다.

## 아래쪽 조각으로 탐색선이 튀는 현상 보완

165번 프레임에서 위쪽 점선과 아래쪽 정지선 잔여 조각이 한 차선으로 묶이던 현상을 확인했습니다. 기존에는 5개 행만 있어도 탐색 창을 유효하다고 인정해, 멀리 떨어진 7개 행짜리 조각이 곡선의 끝점이 될 수 있었습니다.

짧고 가로로 넓은 성분을 차선 후보에서 제외하고 창 높이의 약 25%(최소 8행)를 관측해야 창을 유효하다고 판단하도록 변경했습니다. 떨어진 관측 묶음 중 극소수 행만 있는 것은 곡선 맞춤 전에 제외하며, 화면에 표시하는 창의 유효 여부도 최종 관측으로 다시 계산합니다. 정상 점선 사이의 공백은 유지합니다.

합성 점선+하단 가로 조각, 전처리 완료 입력으로 들어온 7행 조각, 실제 165번 프레임의 하단 오검출 제거를 회귀 검증합니다. 검증용 이미지는 검증 실행 시 updated_results/qa에 다시 생성됩니다.
